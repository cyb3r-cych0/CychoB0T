# Contributing Guide

Thanks for your interest in contributing.

## Ground Rules
- No secrets in code or commits
- Preserve memory isolation guarantees
- Follow env-based configuration
- Keep changes auditable and scoped

## Workflow
1. Fork the repo
2. Create a feature branch
3. Add tests where applicable
4. Update documentation
5. Open a PR with clear rationale

## Code Standards
- Explicit over implicit
- No silent fallbacks
- Fail fast on misconfiguration
- Production-grade defaults only

## What We Welcome
- Routing logic improvements
- Memory strategies
- Observability enhancements
- Security hardening
- Documentation improvements

## What We Reject
- Disk-based secrets
- Hidden global state
- Implicit memory sharing
